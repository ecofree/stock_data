本轮按 P0 → P1 → P2 顺序收敛。本文是当前代码边界，不代表已经补齐
数据库中尚未到达的真实源数据。

## P0 已完成

- 收盘复盘发布与竞价/盘中运行状态分离；非 close 运行不能覆盖
  `reports/daily_review_latest.html`，失败运行只发布状态页，不修改当前复盘。
- `daily_review_last_complete.html` 只在 close 运行确实发布了合格 HTML 时更新。
- 竞价、盘中信号生成明确传递对应 `--readiness-stage`，不再用默认 intraday
  误判 auction。
- 默认概念与成分视图取消未经完整校验的 KPL 历史 fallback。KPL 原表保留给
  回补/审计，不能把局部快照伪装成完整概念宇宙。
- 两融展示要求同一交易日同时有至少两个非 BSE 交易所，并按最新日与更早日
  正确计算变化。
- 特征、候选池、QLib 导入/评估、竞价证据和操作计划等关键写入增加显式事务
  与失败回滚；操作计划的唯一键写入改为可重复刷新，避免 DuckDB 同事务删除后
  重插导致同日唯一键冲突。
- 每个运行清单记录 git、源代码、配置、Schema、Python 和 DuckDB 指纹。

## P1 已完成

- K 线日视图按 `volume_unit` / `amount_unit` 转换；未知单位不再被静默放大，
  非日线周期不再混入 `v_kline_daily`。
- 复盘中的候选和题材时间线标明实际数据日，并优先读取质量门控后的概念视图。
- 页面概念区首屏只渲染前 50 只；其余概念和“加载全部”通过同一 HTML 内嵌
  JSON 按用户动作解析，保持静态自包含，不依赖 fetch 或 sidecar。

  不进入收盘执行门禁的边界；若模型预测存在漏跑交易日，会在当前源数据门禁
  通过后有界追赶最近 20 个可用交易日，避免影子评估停留在旧日期。
