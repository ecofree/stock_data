## 本轮纸面闭环：代码和命令

模块 `trade_system/v2/operator_workflow.py`；入口 `stock-data-paper-desk` 或 `python -m trade_system.v2.operator_workflow_cli`。

```powershell
# 必须是已有、独立的 V2 纸面库，不会创建真实账户。
python -m trade_system.v2.operator_workflow_cli --db <纸面库> export --decision-id <有效原证书ID> --output <新计划JSON>
python -m trade_system.v2.operator_workflow_cli --db <纸面库> confirm --packet <计划JSON> --quantity <数量> --operator <声明操作者> --request-id <固定意向ID> --quote-manifest <本地行情快照ID> --acknowledge-paper
python -m trade_system.v2.operator_workflow_cli --db <纸面库> review --account-id <纸面账户ID> --output <新复盘目录>
```

导入文件不是命令授权：字段严格限定；即使重新计算文件摘要，也必须与本地原始证书逐项相同。风险政策、方向、账户、价格和信号不能由文件替换。确认委托给原 DecisionService，在一个写入线程中复核当前状态及预占。同一计划/意向重试使用固定派生请求 ID，重启/过期后能取回原确认结果；改变同一请求的数量或操作者会拒绝。

确认仅创建纸面预占，**不自动调用 paper_buy/paper_sell，更不创建真实委托**。后续已有纸面订单接口仍需单独显式调用和再次核验。复盘 JSON 关联确认、纸面订单/成交、归因和未送达状态；实际操作者收益留空。静态 HTML 继续不含确认按钮或运行时外部数据依赖。操作者身份是调用者声明，不冒充身份认证。

实际 CLI 演练：`reports/v2-operator-desk-20260910/`。明确使用合成账户、合成报价/容量及规则：5 次 CLI 调用、1 次有效确认、重复确认幂等、100 股假设成交、核对残差 0。不是市场表现或真人业务验收。静态页新增第六区“确认与成交复盘”，展示送达状态、假设成交量、费用和纸面归因差额；真实收益仍显示未导入。

首次演练在报价刚提交但尚未到冻结时点时收到 `required_quote_missing`；证据检查正确阻止导出。演练修正为实际接收完成之后冻结，不改来源时间或放宽风控；原失败目录保留。

## 项目级检查的边界

当前项目的需求基线是 MASTER_PLAN/STATUS，尚未采用 `.ai-project` 控制规范。缺该规范的 checker 不等于已有单测、迁移和安装验证失效，也不能凭空新增“通过”的控制文件。是否引入该规范应作为明确的项目治理决定；当前发布须以实际提交、CI、输入/包摘要与业务验收为证，不因没有额外框架而停止所有可执行工程任务。

真实执行、券商路由和生产切换保持关闭。历史证据的来源指纹不重写；后续源码变化对应新的本地验证记录。
