# 工件保留与不再膨胀规则

## 不可自动删除类别

生产数据库、当前发行、指定兼容回退、原始来源回执、人工资料、真实账户输入、Git历史、失败原始记录、永久guard和被其它批次引用的归档对象，不按日期自动删除。只有完整SHA相同才能认定字节重复；同表数/行数/大小不够。共享归档要看全局引用，不能因某一个批次到期删掉。

旧资料按明确目录/文件清单处置，固定维护窗口、管理员引用检查、实际guard、精确源身份/全SHA和实际隔离恢复均不可省略。原失败/历史时点不改写成新成功。恢复只到新私有隔离目录，不覆盖原库、生产、既有恢复点或开发树。

## 新测试工件的准入边界（不是OS实时配额）

`tools/v2/run_tests.py`及`verify_delivery.py`统一使用系统临时目录下的`stockdata-owned-test-runs/<run-id>`；位于源码之外，以便运行根隔离反例保持真实。每次只有一个目录，拥有owner.json，结束写finished.json；所有子进程禁止写bytecode，新的pycache前缀避免加载旧工作树缓存。

保留证据可在独立archive/report位置，展开夹具不再随每个报告目录复制。当前上限为12个展开run、100000文件、10GiB。占用达到任一上限时，在实际`run-registry.guard`内拒绝新分配，而不是另开目录绕过预算。guard不删除；不按PID或旧时间接管。这是新run开始前的准入检查，单次运行增长仍可能越过阈值；结束后必须核对库存，超限不得再启动，不自动杀进程或删除文件。

成功run的建议保留期：quick 7日、release/all 14日、history/research 30日、stress 3日；失败展开run至少30日。已被新版本替代的成功展开可在另一个精确范围内提前转为全量可恢复归档，原保留期限和失败/原始回执不缩短；永久guard须留在原卷、保持实际文件身份。到期只产生待审核计划，**年龄不是删除许可**。未知owner、缺completion、身份/源码指纹不符、共享引用、包含guard或缺实际归档恢复证明时保留。日志和验收回执长期保留；展开数据退出前进行精确归档和隔离恢复。

`tools/v2/artifact_retention_plan.py --archive-index ... --deployment-state ... --output <新文件>`只读输出库存、预算、保护原因和候选。它没有删除命令。可选的恢复证明必须有真实文件、完整匹配的归档/恢复回执SHA，以及与当前源集合相同的逐文件SHA/长度；只给passed布尔值不会被接受。即使成为候选，真正删除仍须单独范围、时限及同句柄源验证。永久guard须保留原身份、移至明确历史载体位置，不随目录删除。

早期位于源码内的自有测试目录只作历史清理对象，已有失败结果不重写；在明确归档验证前不自动删除。新runner不再往其中写。

## 测试分层不是降低门槛

- quick：明确的短反馈子集，永不宣称完整发布通过。
- release：所有数据、历史恢复和压力安全案例；仅把必须独立依赖的两项历史研究案例交给原research CI作业。
- history/research/stress：可独立运行指定变更域；这些案例仍留在相应完整门禁。
- all：全部本地案例。未知新案例默认进入release，不静默排除。

现有pre-push可显式提供准确完整验证回执路径及SHA，复用两小时内同提交、同字节、干净源码的完整数据/最小核心门。复用前实际复读全部日志/JUnit/wheel SHA，核对当前完整测试收集数和wheel模块内容；没有证据对时仍执行完整数据测试，证据过期/缺件/漂移/零用例则拒绝，不绕过钩子，也不替代独立研究CI。测试收集只枚举用例，不执行另一轮测试或创建展开工件。

发布仍由准确源码、lint/迁移/写者边界、完整数据门、最小安装核心及独立研究CI共同验收。缺JUnit、零用例、源码漂移、错误退出不能变成通过。压力夹具必须标synthetic，不进入生产workspace或业务验收天数。

## 日常数据库备份

日常7份/周锚点4份仅是保留**目标**。旧`retain_qualified_backups`现在只输出候选计划，不按数量自动删除合格恢复点；共享/活动引用、恢复验证和固定维护范围必须另外复核。未知/失败/partial不获恢复资格，但全部占用容量。

同一备份目录使用真实永久`backup-maintenance.guard`把容量检查与分配/最终压缩串行化。缺省32GiB、128文件，保留2GiB磁盘余量，并预留当前原库及最坏压缩副本空间；不通过环境变量自动抬高限额。容量不足时不创建新的大副本、不驱逐旧恢复点，已验证raw保留。原收盘包装器明确记录备份延后，是否继续采集仍按原截止时间/资格规则，不因此变为业务通过。

## 最终日常维护

不新增第六个例行任务，不自动开启PAUSED跟进。每次运行前检查预算；定期人工审阅只读保留计划，按共享引用复用对象；归档后验证恢复入口。当前导航只保留最新状态和证据索引，原过程放历史档，不反复复制全库/全环境/工作树来生成新报告。
