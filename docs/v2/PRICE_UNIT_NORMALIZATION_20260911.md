# 观测记录单位核验与隔离价格层

日期：2026-09-11。实施目录：`D:/accio/stock_data-retirement`。本段只读冻结数据库，未改现网、生产采集、原研究导出、模型和未来样本登记。

## 结论与原因

上一段 [原生来源比较](IDENTITY_SOURCE_PROBE_20260911.md) 发现：同一证券 42 个交易日的 OHLC 与原生返回一致，但库内量/额的数值和声明单位不符；全库诊断显示 2025 年存在混合口径。按年份统一缩放或相信旧字段标签会把错误传播到量能特征、成交额及流动性研究。

本段将该发现落实为**逐条证据绑定的、可重放的隔离规范化层**。实际 42 条记录通过样本单位核验，成交量规范为股、成交额规范为 CNY；3,399,054 条其余记录仍未覆盖/未认证，不外推转换。这里的“通过”只表示观测记录的数值与来源单位相符，不是历史身份、原时点可得性或交易资格认证。

## 实现与取舍

入口：`tools/v2/normalize_price_units.py`。回归：`tests/test_price_unit_normalization.py`。

1. 直接重放已封存的 16 请求包，校验完整成员、摘要、请求参数、时间、字段、返回代码和日期。拒绝合成来源包；不把上一段诊断 JSON 当作独立事实输入。
2. 当前策略明确限定 `302132` 和两个原观测窗口（2024-01-02—02-22、2025-02-10—02-21）。只有**相同请求代码、相同证券日**的 HiThink 与中继日线共同覆盖，才可核验；不使用 `300114` 别名补缺。
3. OHLC 必须与原表一致；量/额以 HiThink 为优先依据，中继成交额允许最多 0.50 CNY 的原精度差异。重复原生来源必须一致，不继承中继的舍入容差。
4. 对每行分别识别量和额的转换系数，只接受唯一匹配的预设比例。空值、零值、无法识别的比例、价格/来源冲突、非原始价格、代码冲突均不能通过。比例拟合保留绝对与相对浮点容差及原生残差；不把该规则当作所有来源的单位字典。
5. 原代码、日期、OHLC、量/额原值、旧单位标签、复权状态、provider 标签、接收时间全部保留；每行绑定原记录摘要、原生/中继回执文件及摘要、回执接收时间和转换系数。旧 provider 标签只是原值，不被当成已认证采集出处。
6. 新输出目录不可覆盖，文件封存；验证会从原始回执和同一个数据库重新计算整层。数据库变更、回执变更、重封存后的伪造转换结果、代码版本变化都会使旧层不可直接复用。
7. 只向绑定的原数据库连接建立 `TEMP verified_price_units`，主键为证券/日期，字段明确命名 `volume_shares`、`turnover_cny`。未核验记录不进入该临时表；全量左关联时缺失返回 NULL，严禁回退到原始量/额。连接必须只有一个实体数据库且路径匹配；临时表关闭连接后消失。

范围外/未核验记录的处理不是静默删除：输出包含源表总数、范围内行数、通过数和其余未认证数；范围内失败行保留原记录、原因及空规范值。该层是有限覆盖的修复材料，不是全市场完整价格表。

## 重放方法

在隔离目录使用 `D:/anaconda/python.exe`：

```powershell
# build 的 output 必须是全新目录，不能覆盖既有证据。
D:/anaconda/python.exe tools/v2/normalize_price_units.py build --receipts tmp/identity-source-receipts-20260911-r1 --db tmp/ed47-followup-measure-20260911-r2/source-copy/kpl_data.duckdb --output tmp/normalized-price-units-NEW

D:/anaconda/python.exe tools/v2/normalize_price_units.py verify --receipts tmp/identity-source-receipts-20260911-r1 --db tmp/ed47-followup-measure-20260911-r2/source-copy/kpl_data.duckdb --output tmp/normalized-price-units-20260911-r1
```

SHA 封存只证明本地证据一致性，不是供应商签名或防恶意伪造认证。HiThink 行未回显证券代码，其身份绑定仍只是请求代码；不能把本段数值吻合解释为完整证券身份合并证据。
