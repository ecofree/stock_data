# 持仓退出统一风控与三账归因

状态：本段 **reduce-only 纸面退出证书链、结算归因投影及合成入口已实现**；不是完整自动退出策略、真实账户验收或正式选股效果验证。

## 本段解决的问题与取舍

上一段纸面买入需要 DecisionService 确认，卖出却能经通用 paper_event/submit 直接进入账本；三账虽分开存储，但没有统一损益核对和逐单执行归因。按用户“继续下一段”的授权，本段封住卖出直通入口，在同一 DecisionService / decision_certificate / operator_action 内实现退出提案和确认，新增数量预占，补上可审计的三账投影。

减少既有风险不要求再有买入信号，不受买入总仓位/单票仓位上限阻止；但仍要求有效账户、可卖股数、报价、声明交易日历/规则和每单数量上限。没有自动生成或校准止盈/止损阈值；`manual_reduce` 与显式 `price_below` 都只是纸面政策。

## 当前实现

- **一个决策入口**：`DecisionService.propose_exit` 生成 side=sell / reduce_only=true 的证书，复用既有 confirm 事务、幂等请求和原证书限制。退出不借用过期/失效的买入信号；政策版本、理由引用、有效期和可选价格条件冻结后不能同版本改写。
- **数量预占**：V2 加法迁移 5 保存退出政策和 exit_reservation，数量与买入资金分表分单位。可卖数量先扣活动卖单，再扣 held/unknown 退出预占。整手/显式允许的零股全卖按账本规则验证，不能重复确认超卖。
- **交付重验**：paper_sell 只接收成功的卖出确认，再核对政策、最新报价版本、账户快照、账本哈希/配置、估值时效、可卖量和预占状态。消费成功时，预占转为 paper_order、账本事件、账户投影同事务提交；注入投影失败后全部回滚。
- **禁止绕过**：新 paper_event/submit 不再允许买卖任一方向，必须走 paper_buy/paper_sell；买入接口不能消费卖出确认。历史已经落账的直接卖单保留、可重建，不追改过去事实。
- **未知状态保守保留**：未交付的退出预占若标为 unknown，不因有效期到期而释放。mark_exit_unknown 不等于撤单确认。完整人工解决/释放预占工作流和界面仍未实现，不宣称运行闭环已经完备。
- **核对而非“总分”**：attribution 投影按账本哈希重演，检查订单/成交数量、金额、费用控制数，绑定确认与原始信号。组合公式为：已实现损益 + 未实现损益 − 初始未实现损益 + 分红收入 = 剔除外部入出金后的观测损益。
- **费用不重复计算**：逐单“执行价格偏差贡献”只比较冻结确认价与实际纸面成交价；买入低于基准/卖出高于基准为正，费用单列。该表是执行诊断，不能再次加到已经计费的组合损益中。
- **未知就保留未知**：未成交数量、blocked / not_delivered_or_unknown 确认状态显式保留；未成交机会成本不估计。确认至成交加权秒数是观测延迟，不是因果择时贡献。未定义评价期限/反事实，不能从已成交信号推断选股胜率、alpha 或失败样本表现。
- **真实与纸面隔离**：真实人工账标为 not_imported_into_this_projection，trades/return 均为 null；纸面操作记录不当作真实成交。其他系统有无成交不由本投影推断。

主要源码：`trade_system/v2/exit_policy.py`、`decisions.py`、`paper_storage.py`、`attribution.py`、`service.py`。`reporting.project_review` 在存在纸面账时附上归因 JSON；本段未设计/验收新的 HTML 退出操作卡或交互归因界面，交付形态为 JSON 与 Markdown。
