## 关键行为变化与取舍

### 不再保留第二条下单或人工计划生成通道

`trade_system/paper_execution.py`、`scripts/paper_order.py`、`trade_system/daily_loop.py` 是拒绝式退役入口；没有 `allow_legacy` 等逃生开关。原实现可从基线 Git 读取，不需要放进正式运行包。历史人工事实不迁移、不清空、不自动“修复”。

旧式连接统一经 `trade_system.db_utils.legacy_connect`：打开可写连接前先只读识别代际，并在返回连接前复核。停机 V2 文件也拒绝；纯只读审计允许。这是项目内误路由防线，不是对任意第三方程序的文件权限沙箱。当前检查覆盖已跟踪源码中的显式连接调用；动态外部程序和系统任务仍需部署审计。

### 时间和资金语义

不再通过时间取整解决时钟竞争。事件输入推导和 manifest 使用同一次截止时间。`effective_at` 在去重前验证；相同来源修订键的数值、原文或生效时间不同必须报冲突，不冒充重试。

资金增量使用“截止时间减固定窗口”的锚点和最新端点，不使用最近两条任意样本。计数周期 `counter_epoch` 必须明确，周期或指标版本切换不算资金流出。边界容差须显式配置且小于窗口，默认不自动放宽。

策略算法版本、参数集、交易日、机会实例和运行范围分别记录。前一天过期实例不封死次日机会；历史未命名实例隔离保留，不改写旧记录。

### 预占不是成交

`close-unsent` 只关闭确定未送达的 held 纸面预占，重复固定请求幂等；unknown 和已送达均拒绝。`reconcile-paper-unsent` 是另一个明确操作：只能在完整本地纸面账全量校验后，以未出现对应订单为狭义证据关闭 unknown；不能用于外部券商或真实账户，不能凭用户传入“未成交”标记放行。已送达订单必须走订单对账。

关闭事件有自己的身份和摘要，复盘区分确认、预占关闭、已送达订单与假设成交。取消不生成新订单；重新考虑机会需要新的有效证书。

### 运行成本和超时

按数据集、证券、时间限制冻结范围，超过 100000 条事实拒绝。纸面账每 64 个事件形成检查点；恢复时校验配置、快照、原始存档、历史日志前缀和尾部重放。保留 `paper_verify` 独立全量重放；快照损坏不会静默忽略。

关键命令保留额外队列容量，退出命令也有专用位置。截止时间在执行前和事务提交前等安全边界检查。进行中的原生调用可能仍超时；不强杀写者、不删除锁、不把客户端超时当作“未应用”。`Service.health()` 不经过队列，可看到运行时间与超预算状态。

合成 128 条现金事件、重启后各 5 次测量：检查点读取中位约 0.010 秒，独立全量重放中位约 0.438 秒，结果一致。仅为该现金事件夹具，非行情吞吐、最坏订单账户或实盘延迟结论；Python 内存统计不含全部本地库内存。证据：`tmp/checkpoint-benchmark-r1/benchmark.json`。

### 派生指标与 QLib

新增 `qlib_stock_flow_features_v2` / `qlib_sector_flow_features_v2`，不覆盖旧表。加速度改为两个等长五观察点窗口之差；来源或指标定义切换分段；不足历史和未经确认的单位/分母不补零，输出明确质量状态。这里的窗口是观察行，不宣称已认证连续交易日。

新 QLib 导出只消费达到显式候选质量条件的 V2 表。训练阶段全缺失或常量特征直接拒绝；不把“库能训练”当作“特征有信息”。原四组负结果和冻结样本不改写。本次未运行新 QLib 拟合，未登记新的未来样本，更未验证选股增益。
