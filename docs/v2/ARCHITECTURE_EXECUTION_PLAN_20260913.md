## 2. 本次范围和必须补充的设计决策

目标仍为现有 V2 的模块化单体。沿用获取、标准事实、市场分析、研究、操作账户、视图发布六个职责边界；以用户任务决定移交范围，不规定每个边界必须新建目录。

采用以下具体决策：

1. 市场事实和会话独立于模型。市场日期来自合格交易日历和数据快照；模型只是可选证据。没有模型时，仍能打开市场、保存人工关注、查看旧回执。
2. 关注范围独立于预测范围。人工关注和持仓即使退出研究池，也必须保留。预测证券、关注证券、持仓证券分别标识其来源。
3. 保留旧事件身份。新对象以机会/观点实例为主体；已有 `note_id`、`prediction_id`、接收时间及回执内容保持不变，通过兼容读取或关联事件接入，不能批量改写原记录和哈希。
4. 复用账户核心时遵守实际能力。当前 `decisions.py` 明确只支持纸面决策，拒绝 live 账户；真实账户在本计划中用于导入、对账和风险展示，券商自动委托不在范围内。
5. 暂停向 `research_product.py` 增加新业务规则。HTTP、CLI 和任务入口调用明确用例；来源选择、标签公式、账户规则由对应业务所有者维护。按职责迁移，避免机械拆文件。
6. 闭市状态与采集故障分开。显示交易日历依据、最后有效会话、行情时间、是否处于连续交易时段；闭市期间保留最后会话数据供复盘。交易时段的当前价仍需独立通过时效校验。
7. 空值必须有原因。统一区分 `source_missing`、`source_conflict`、`expired`、`not_applicable`、`not_implemented`。交付必需字段不能长期用 `not_implemented` 伪装成外部缺数。
8. 源优先级按数据产品执行。相同口径的合格来源遵循 HiThink 官方、TuShare 中继、其他的顺序；不具有同等定义的资金、分类和事件不参与强行替代。
9. 现有固定发布包与本次整改候选分别验证。旧包的批准不覆盖新内容；最新分支的 CI 失败也不能直接证明旧固定包存在相同缺陷。

## 5. 功能移交 M1：数据 → 市场 → 人工关注

预计 2–4 个工程工作日。这是第一件必须交给用户的完整成品，不能延后到整轮结束。

### M1.1 解除模型依赖，完成最小独立观点对象

修改落点：启动器、`research_product` 的 configure/update/publish/observe 用例、`market_workspace`、`research_journal` 与页面读取。

- 启动器不再要求 `research-current.json` 存在。日常运行环境不导入训练器；研究操作按需加载依赖，依赖异常有自己的状态。
- 市场更新独立接收市场来源、会话和截止时点；允许研究证券集合为空。
- 新观点最少记录证券身份、观点/机会 ID、证据快照引用、理由、条件、接收时间、声明操作者、版本和请求 ID；预测引用为可选字段。
- 无新模型、模型过期、模型文件损坏时保留已有合格市场快照和人工事件；研究卡片显示具体状态。
- 旧记录兼容读测试与“证券退出研究池仍有关注”测试随本功能完成。

### M1.2 接回复盘必需信息

- 第一组：市场广度、成交、涨跌停、最高连板、梯队分布、题材涨停数和最高板。
- 第二组：昨日固定队列的后续表现、题材轨迹与概念资金。每组均标明样本范围、来源定义、数据日期和排除原因。
- 对具备合格数据的字段接通计算；不足时显示具体原因。市场情绪模型如尚未验证，保留未评级，不能用广度或宽泛概念生成替代结论。
- 当前成员只能用于其有效范围。历史成员未经核实的题材指标，不授予历史时点资格。

### M1.3 数据产品复用与四工作区的第一步

- 沿用现有回执、标准视图和发布清单，补充数据产品身份：提供者/实际来源、渠道、接口版本、证券范围、会话、字段、单位、复权、授权范围与修订版本。
- 请求原因限定为首次准备、缺口、时效到期、源修订、独立核验。相同有效事实被复盘/观察/研究消费时不重复取数；独立核验保留独立来源和时间。
- 共用锁只约束同一写入资源；各数据产品有自己的刷新要求，避免用一个“上次预测日期”控制所有采集。
- 先交付独立盘后复盘和观察任务视图。保留同一 HTML 内联数据与同一服务，使用选中对象和索引联动，避免复制整份载荷。
- 显示闭市、最后会话、盘中尚未验收和真实采集错误，周末不把所有旧报价标成整个系统故障。

**用户实测 G1：** 在没有 QLib、没有任何模型的环境中，打开复盘 → 查看题材及两只证券证据 → 保存一条人工关注 → 取得回执 → 重启后找回原文与条件。给定合格涨停/梯队输入，相应字段完成计算；一个证券坏数据只影响其关联项。此时即可交付观察使用。

## 6. 功能移交 M2：关注 → 条件计划 → 账户风险 → 结果

预计 2–4 个工程工作日。依赖 G1 的独立观点身份和快照合同。

### M2.1 统一对象与事件生命周期

- 在现有 journal 与核心记录能力上建立关联：观点/机会 → 关注条件 → 计划版本 → 账户风险核对 → 人工确认 → 成交/取消/未知事实 → 后续复盘。
- 计划至少绑定观点、证据、有效期、价格条件、失效条件和账户版本；可保存无账户的观察计划，涉及数量和资金的可行性保持待核对。
- 条件状态明确区分未到期、满足、失效、过期、数据不足。价格条件可由合格事实评估；文字或主观条件由人确认，程序不得猜测“已满足”。
- 所有事件追加、幂等；修订不覆盖事前记录，确认不等于成交；未知委托占用或不确定状态不能自动释放为可用资金。

### M2.2 接入已有账户与决策核心

- 明确账户导入、只读快照、风险评估、纸面预占和确认各自的唯一所有者；同一数据库只保留一个写入所有权。
- 真实账户展示现金、冻结、持仓、可卖和未完成委托，显示快照有效期和完整性；缺失资料时显示未知。
- 工程验收用明确标注的隔离合成账户；真实账户接入验收待用户提供资料，不影响观察和计划工程。
- 保留 V2 纸面模式限制。真实账户的自动许可、资金预占和券商委托不随 UI 接通而开放；这部分不纳入本轮完成标准。
- 删除或拒绝被接管的旧默认写入口和仓位推导，不恢复旧业务开关。

### M2.3 观察台形成完整任务区

- 首先展示已有敞口、未知委托、账户冲突、失效和到期事项；再展示新机会。
- 处理队列、关注/持仓/计划和选中证据联动。草稿和选中对象跨刷新稳定，保存回执独立于页面发布。
- 原预测队列的价格复盘继续保留；独立人工观点拥有自己的后续结果，缺少未来交易日时显示等待。

**用户实测 G2：** 无账户能保存和复核关注计划；隔离纸面账户可完成风险核对与已有纸面确认流程；过期账户、冲突账户和未知委托会正确约束相关动作。一次模型发布失败不会使原观点、计划或持仓消失。旧人工回执内容和身份逐字节保持。

## 7. 功能移交 M3：共同研究算法 → 四工作区 → 发行与退出

预计 3–5 个工程工作日。共同公式提取可在 M1 期间准备，最终集成依赖已冻结的数据和对象合同。

### M3.1 两个输入适配，共同特征和标签算法

- `research_dataset.load_history` 与 `research_recent.load_receipts` 保留各自输入职责；规范化后调用同一个特征/标签装配实现。
- 共同实现承担 Alpha 拼接、精确交易会话目标、时间列、资格掩码及元数据结构。21 日价格、5 日资金、61 日 Alpha 依赖通过显式策略保留。
- 精确目标基于完整交易日历定位 T+1/T+2。停牌、缺价、上市边界、尾部未成熟保留原身份，不按“下一条存在的记录”跳过缺失日期。
- 普通历史研究、近期研究和价格独立研究保留各自冻结队列；共同算法不等于强迫共用最大窗口。
- 删除重复 metadata 生产者。新产物使用一个权威清单，兼容读取旧 `dataset.json`，不改写冻结历史目录。
- 独立价格算术核验继续使用独立实现和已冻结样本，不能调用共同标签函数给自己证明。

### M3.2 按数据价值推进 QLib 研究

先完成现有基线/价格/资金/Alpha158 的研究合同和展示消费，再逐族引入已经核实权益和时点的数据：

| 顺序 | 数据族 | 进入产品的用途 | 研究准入条件 |
|---|---|---|---|
| R0 | 现有价格、资金、Alpha158 | 候选横向比较及基线对照 | 同身份样本、窗口与成本假设明确；保留未显示优势的结论 |
| R1 | KPL/THS 题材、梯队、竞价或事件 | 机会解释、题材轨迹、事件模式 | 事件时间、来源定义、成员版本可核实 |
| R2 | TuShare 生命周期、筹码、融资及风险专题 | 排除条件、资金/风险背景、专题对照 | 单位与发布时间完整；不同资金定义分别评价 |
| R3 | easy-tdx 等分钟或流动性数据 | 观察条件与流动性研究 | 权益、覆盖、时间粒度和实际底层来源已验证 |

每族必须声明消费者、字段定义、发布时间、覆盖、成本与缺失方式。没有可验证历史时点的数据先用于当前解释，前瞻收集后再评价；不能回填成历史已知因子。每次只改变一个主要因子族，冻结实验后再运行，记录负结果。

R0 属于本轮交付；R1–R3 按准入成熟度推进。字段合同、消费者接线和采集能力可以完成，独立未来效用由样本成熟决定。不得为了如期宣布完成而扩大选股优势结论。

### M3.3 完成两主两辅与整套功能验收

- 两主：盘后复盘、观察/计划台。两辅：研究实验、数据运行。共享事实、对象、筛选和证据引用，不各自再生成一套判断。
- 首屏保留日期、范围、重要变化和影响判断的风险；模型指标、源诊断、版本和日志进入对应辅助区。
- 合格自包含导出保留数据日期和范围。在线保存、离线导出、未保存草稿分别呈现；账户敏感数据只进入用户明确选择的导出范围。
- 初拟性能目标：指定机器真实载荷下首屏可交互不超过 2 秒、选中证券/题材切换不超过 200 毫秒、普通无竞争保存回执不超过 1 秒。M0/M1 实测基线后固定测量方法；不以缩减必需数据或取消持久化换达标。

### M3.4 固定发行与旧职责退出

- 对每项能力复核 CLI、HTTP、任务、动态导入、文档、恢复脚本和默认生产者，最终形成“新调用路径 + 已退出路径”的同提交记录。
- 干净检出与安装、旧数据读取、新事件写入、升级及回滚均绑定同一版本。回滚必须保护新增事件；不把新格式不可读的旧包称为可用回滚。
- 准备发行清单、依赖锁、关键配置、输入合同、模型/数据引用、目标任务和回滚步骤。原始数据与凭据不进入代码仓库。
- 自动研究身份只读取源数据/模型/配置，不能写真人事件；人工记录入口拥有其必要写权限。安装后使用实际任务身份验证 ACL 和文件/数据库行为。

**最终 G3：** 各必需功能实际完成，CI 和目标环境均有同版本结果；新职责已接管，旧默认职责确实退出；升级/恢复后原人工事件仍可读。真实账户、交易日表现和模型独立优势按各自证据继续标记，不纳入统一百分比。

## 8. 执行组织、依赖与交付节奏

三条工作线是责任分工，并不要求启动多个代理或多套项目：A 负责事实与获取，B 负责业务对象与功能接管，C 负责研究、视图和交付。一个集成人维护公共合同、变更范围和最终证据。

| 阶段 | 主依赖 | 向用户交付的结果 | 必须一起退出 |
|---|---|---|---|
| M0 | 当前审计和固定提交 | 可复现 CI、明确能力清单 | 模糊测试环境和混用通过状态 |
| M1 | G0 | 无模型可复盘、比较和保存关注 | 市场/关注对模型的强制父依赖、必需字段未接线 |
| M2 | G1 的对象与快照 | 条件计划、风险核对、原判断与结果 | 旧仓位推断、重复人工对象和业务许可 |
| M3 | 共同合同与前两次交付 | 共用研究算法、完整工作区、可部署版本 | 重复构建、重复元数据、无消费者旧默认入口 |

初始工作量估计约 8–15 个工程工作日；历史动态调用及账户兼容存在额外 2–3 日不确定性。第一份独立可用产品目标在 M0+M1 完成时交付，约 3–5 个工程工作日。此为排程估计，G0 完成后按实际依赖重新校准；真实交易日、账户和批准部署窗口另计。

每次报告只包含：用户新增可用任务、接管/退出对象、实际结果、未关闭的具体阻碍。每次移交一个可运行版本；不要等三次全部完成才让用户使用，也不以单个适配器或检查器增加作为一轮产品交付。

## 10. 最终必测任务清单

1. 无 QLib、空模型目录：复盘、手动选择证券、关注保存和原回执可用。
2. 模型损坏/过期：市场、原观点和已有账户事实仍可查看，相关模型状态正确。
3. 退出研究池：人工关注和持仓保留，模型覆盖单独显示。
4. 同快照三消费者：数值、单位、来源、会话和修订一致，新增网络请求为零。
5. 重复提交和故障重试：同请求只有一个事件；持久化后渲染失败仍能查看回执。
6. 可用涨停/梯队/历史队列输入：复盘得到可复算结果；未实现不能混为数据缺失。
7. 一处数据冲突：仅阻断依赖此事实的字段或动作，原文和其他已合格事实保留。
8. 闭市/日历未知/交易时段过期：三种状态各有清楚依据与用户含义。
9. 两种输入适配：同一标准输入的共同特征、目标和资格完全一致；不同队列独立保留。
10. 无账户、过期账户、纸面账户、真实只读账户：能力边界正确，确认与成交不会混淆。
11. 新发布失败或升级后回滚：人工事件、旧回执、冻结队列和最新可读格式受保护。
12. 实际目标任务身份：源库/模型/配置拒写、真人目录拒写、指定研究输出可写；旧默认入口不再执行被接管职责。
