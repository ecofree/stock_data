## 核对与实现

- TuShare：[daily](https://tushare.pro/document/2?doc_id=27)、[suspend_d](https://tushare.pro/document/2?doc_id=214)、[dividend](https://tushare.pro/document/2?doc_id=103)、[stock_basic](https://tushare.pro/document/2?doc_id=25)仅列入明确的只读查询白名单。空行情/复牌记录不推导成交，非全天停牌不推导全天缺行情；现金使用税前口径，实施状态与除权日必须匹配。

实现：`trade_system/v2/native_gap_sources.py`、`native_gap_run.py`；入口：`tools/v2/run_native_gap.py`。保留前段 gap_evidence/gap_audit、组合、QLib 和 PaperBook 实现不变，以新模块连接。

原生业务状态、表头唯一性、行长度、代码/日期、原始价格和事件语义严格检查；不补列、不把错误当空成功，不借缺口回填随意扩大日期。送股只保留观察和限制，不能当成当天立即可卖的 split。

归档链为：无密钥请求配置 → 原生响应 bytes → 映射 JSON（含原行号）→ 结构化响应 → 引用 native SHA/版本的证据 → 裁决。验证入口重新从 native bytes 计算映射，不仅比较最终文件名。相同日期的现金事件使用跨源稳定 ID；金额表示规范化，避免尾零产生假冲突。

新的 source_event_at/provider_received_at 表示本次 **HTTP 响应观测事件**，不是伪造的历史公告发布时间；市场有效日单独保留在 claim。未提供的原始发布/首次接收时间仍缺失，旧时点回放不能使用今天收到的历史资料。

## 请求约束与首轮纠正

两家现有凭据均已配置；只在内存使用。允许域名固定为已核对的 HTTPS 主机；不同中继地址拒绝自动发送凭据。curl 配置通过 stdin 传入，认证头/POST token 不进进程参数，TLS 验证保持启用、不跟随重定向。若响应回显完整凭据则不落原文；两轮产物扫描无实际凭据匹配。

原预算为最多 28 次传输尝试；每轮最多 240 秒启动预算，单请求 curl 最多 15 秒、进程兜底 18 秒、响应最多 4 MiB。与既有中继 SQLite 限流表协调，争取限流槽最多等 5 秒；没有修改生产 DuckDB。这里的 transport_attempts 包含进入传输阶段的尝试，不是服务端计费对账。

首轮只按端点停止错误，实测暴露两点：单标的未知不应该停止其他股票；账号级 429 不应该继续逐端点尝试。已修正为标的错误不外扩、401/403/429 等来源级停止；续跑前要求来源冷却不少于 60 秒。仅允许一次与同一案件包绑定的续跑，继承已用请求预算和原证据，不重新抓取已有候选，不改旧 available_at；候选仍不是已解决案件。
