# 复权与资金数据补齐：首段真实闭环

本段继续用户已批准的整改顺序，只修改隔离研究链。核心安装包仍为 0.3.1；新研究模块不进入核心 wheel。没有修改生产库、任务、账户、历史冻结实验或启动模型训练。

## 原因与处理

上一段补齐日历后，2024-01-02 至 01-05 导出的 20,035 行仍没有可计算标签，原因是来源库缺少对应每日复权因子。资金字段还需要把原始接口单位、实际接收时间与消费者绑定。

按 web-access 技能核对官方定义：HiThink 公布的是公司行为事件流，不能直接替代每日复权因子；其当前公开接口表也没有与 TuShare moneyflow 对等的逐单大小资金流接口。因此使用既定第二优先级 xiaodefa 中继查询 TuShare `adj_factor` 与 `moneyflow`，不是改用未经说明的兜底。

- [TuShare 复权因子](https://tushare.pro/document/2?doc_id=28)：按单个交易日查询每日因子。
- [TuShare 个股资金流向](https://tushare.pro/document/2?doc_id=170)：所用金额字段单位为万元，单次最多 6,000 行；返回达到该界限时本实现拒绝声称取全。
- [HiThink 接口能力表](https://github.com/HiThink-Tech/Financial-API/blob/main/docs/api/capability-map.md)：记录来源能力差异，不能把字段名字相似当作口径相同。

## 已实现与实际取数

`trade_system/v2/research_receipts.py` 提供受限历史补证：从封存日历确定起止区间及精确 T+2，最多 10 个交易日、20 个请求，每请求一次、15 秒套接字超时、8 MB 读取上限，禁止重定向。失败保留安全错误类型及已接收文件，不封存为完成包；凭证不落入采集文件或异常文本。

首段实际请求 2024-01-02、01-03、01-04、01-05、01-08、01-09，共 12 份成功响应：

- 每日复权因子 32,189 行。
- 资金流 30,535 行。
- 证据目录：`tmp/research-repair-receipts-20260911-r1/`。每份响应保留字段、数值、请求身份和本次真实接收时间；报告可从归档数据重新推导。

严格拒绝重复代码、错日、非有限数、非正复权因子、负的买卖总额、布尔数值及可能截断的返回。资金净值允许负数；缺失资金字段仍为空。合成客户端带 `synthetic_fixture` 标记，不能供正式历史补证导出消费。

## 导出实际消费

在 `scripts/export_qlib_features.py` 新增 `--research-overlay`，必须搭配同一摘要的 `--calendar-overlay`。源库以只读方式打开，修复表只存在于当前连接的临时空间。

1. 修复导出仅使用封存的每日因子，不把新因子锚点与旧因子混用。
2. 资金字段按明确的万元口径乘 10,000 转为元；不与旧库未认证单位的资金值混用。
3. 五日资金指标要求五个连续交易日、五个非空值；不足五日或中间缺日保持 NULL。
4. 新标签版本为 `market_session_aligned_v4_sealed_repair`，元数据记录补证摘要、逐日覆盖、来源表和金额单位。

实际新导出：`tmp/factor-money-repaired-export-20260911-r2/`，范围 2024-01-02 至 01-05，5,009 只证券、20,035 行，**可计算历史标签从 0 恢复到 20,035**。这只是计算输入修复，不是收益改善、执行资格或模型有效性证明。
