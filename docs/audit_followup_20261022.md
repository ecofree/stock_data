# 2026-10-22 复核后五项修复合同

范围为开发树，承接本轮复核报告 F1–F5。保留既有修改；不迁移生产库、不改计划任务、不恢复运营、不重新启用退役入口。测试与页面产物保存在项目外，最终执行结果以外部验收报告为准。

## F1：板块目录完整性（P1）

`collect_sector_plates` 先验证整个响应的结构、标识、重复项和元数据类型，再在事务内合并。任一坏行拒绝整批；无响应和空列表保留旧目录；返回合并后的完整保留集合供下游使用。采集记录明确标记为 `merged_unverified_completeness`。

现有接口没有可信的全量/退役合同，包括 `complete=true` 在内的未核验声明都不能授权删除未返回的板块。因此本入口不支持全量删除；保留旧标识的代价是可能继续尝试已退役板块。真正删除需独立完整性证据和维护方案，不能添加布尔开关绕过。

同根复查发现排名及其回退也会按日期删除未返回板块/成员，已扩展为按业务键合并；排名与内联成员在同一事务发布。回退复用目录校验并使用保留后的板块集合；完整入口先验证目录，再执行排名。该保护同样意味着未核验的成员移出不会自动删除，应由以后明确授权的快照维护合同处理。

仅返回的记录刷新接收时间，未返回记录保留原时间；成员信息更新不提供报价时，返回键上的旧报价置为未知，不能跟随新时间冒充新报价。失败仍回滚这些更新。

## F2：市场计数、评分和门禁资格

`market_contract.py` 是五项计数的共同资格定义：涨停数、跌停数、上涨数、下跌数、连板数均为有限非负整数，且源没有声明部分/估算状态时，`market_daily_status` 才为 `available`。零是有效观测，NULL 不是零。`real_partial` 即使凑齐数值仍不获得完整资格；价格阈值派生的全量池汇总仍为 `estimated`。

规范视图、三个市场状态候选关系、V2 工作区和复盘页共用该定义。readiness 检查最新的 as-of 快照，不能从更早的完整行或原始表别名恢复资格。资格与新鲜度分别记录，缺失时间或过期仍被拒绝。

评分额外需要自己的有效输入：赚钱效应需要 0–100 的成功率和非零涨跌家数分母；急跌风险需要 0–100 的炸板率和有效破板、炸板计数。缺失或非完整市场状态使相应评分为 NULL，并输出独立状态，不再用默认零表示低风险。五项计数完整只代表这个组的数据合同，不代表研究有效或交易可用。

正向历史测试夹具已补足这些真实必需字段，保留原验收断言；新增反例明确拒绝只有日期、缺字段和估算数据。未放宽门禁以迁就夹具。

## F3：原生连板数安全转换

xiaodefa 原生 `limit_times` 必须为有限正整数且能安全转换为规范 INTEGER；使用 `TRY_CAST`，不依赖 SQL 条件执行顺序。无法解析的接收时间也不进入候选。坏行仍留在原始表，其他合格来源继续参与 HiThink > xiaodefa > 其他的排序。INT32 可表示不等于经济合理性认证。

## F4：日终采集身份与心跳

wrapper 分配唯一采集 attempt ID，并将同一 ID 与交易日传入预检、集成采集和全部通知。备份编号为采集编号追加 `_backup`，两份回执角色分开并在日志关联。心跳明确标为 `collection_only`，`acceptance_verified=false`；不能代表发布验收或备份资格。

检查器可使用 `--run-id` 校验预期采集回执，错号为 WRONG_RUN，错日为 WRONG_SESSION；失败/进行中不因旧成功而通过。暂停、休市保持中性。这里只修改脚本，不修改任何实际任务。

## F5：成员明细回退合同

有成员快照时展示快照成分；缺快照、快照查询失败或缺当日成员行情时，将涨停样本统一映射到 `code/name/pct`。代码关联的连板及封板时间随之保留。页面明确标注样本范围，不称作“全部成分”；空数据有空状态。HTML 转义、脚本 JSON 转义和全部交互数据内联约束继续生效。
