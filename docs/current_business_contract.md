## 统一状态

- market_view / flow_observation 是具体用途资格；不得替代严格数据认证或独立资金确认。
- analysis_ready 表示原严格分析门槛，仍须相应数据与资金证据；不授权执行。
- execution_ready 在当前研究链始终 false。legacy_execution_requested 和 candidate_pool_executable_candidates 只记录历史输入标记。
- 运行成功、数据可用、页面发布、研究有效和真实账户对账各自保留证据。
- 旧兼容函数参数保留以便读取历史记录，不能成为重新启用入口的开关。
- 旧人工复盘没有所见行情绑定时明确显示未知，不追补证据；新复盘只在没有已发布行情时允许明确 unbound。绑定是接收时封存事实，不认证供应商原始发布时间。原判断修订或人工失效阻止新计划；旧成功请求、原文与回执保留，重新打开和后续价格好转均不复活旧计划。

## 产品与完整性

产品声明见 [产品消费合同](business_product_contract.md)，来源选择见 [权威矩阵](source_authority_matrix.md)。
运行回执新增数据产品 ID、合同哈希和明确消费端；产品声明不代表实测消费。
市场快照与发布清单保存被实际投影字段的哈希，覆盖明确未知值；它不等于合格源行数量，也没有伪造 HTTP 请求到行的逐条血缘。
只读审计使用 `--product-usage <运行回执...> --publication-usage <publication目录...>`
复读当前发布指针及原件。旧产物缺少记录保持未测量；仅按声明产品对应，不推断某次采集已经发布。

成员合同记录请求日、快照日、年龄、声明范围完整性与成员键指纹。
沿用合格历史快照可用于有界复盘，但不证明当日成员未改变。
没有生效时间原件时 effective_from/effective_through 保持未知；部分 KPL 合并结果不能推断成员退出或补位为完整 THS 快照。

## 历史数据与隔离迁移

本轮只在新建隔离库演练 0016、0017，不读取或复制生产库。

| 历史疑点 | 处置原则 | 后续验收 |
|---|---|---|
| 未知来源或复权 | 保留原值，隔离不合格用途；寻找原始产品凭据 | 无凭据不猜测标签，跨产品不合并 |
| 完整产品键重复 | 比对数值与原始回执，冲突进入裁定清单 | 迁移失败整体回滚；不得自动删行让索引通过 |
| 旧市场统计缺血缘 | 按 market_contract 判定；不刷新旧事实时间 | 部分、未知与显式零分别展示；有效 JSON 仍须字段级核验 |
| 板块成员/强度重复 | 按日期、板块、股票及来源核对 | 不覆盖正确值，不因响应缺席删除旧键 |
| 缺完整性回执 | 保持未认证，补供应商范围和时点证据 | 不充当完整分母或成员退出证明 |
| 旧纸面错误成交 | 保留原始账与已知问题，另行设计更正证据 | 本轮不改历史账，C3 不自动继承纸面结果 |

隔离演练覆盖多来源、多复权共存、空库/缺表、重复迁移、重复键失败回滚、未知血缘保持未知、迁移前后业务值不变。
生产迁移、发布绑定、任务变更与运营恢复不属于阶段 1、2 的完成许可。
